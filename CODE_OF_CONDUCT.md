# Code of Conduct

## The short version

Be decent to people. Argue about code, not about each other.

## What is expected

- **Assume competence.** Contributors arrive with different backgrounds and
  different amounts of Rust. "You should already know this" is never a useful
  sentence.
- **Criticise the work, not the author.** "This allocates on every frame" is
  review. "This is amateur work" is not.
- **Say why.** A rejected patch with a reason teaches something; a rejected
  patch without one just discourages.
- **Accept that maintainers say no.** Scope is a real constraint, and a good
  patch can still be the wrong patch for this project. It is not personal.
- **Respect the effort behind a report.** A vague bug report is someone trying
  to help with the information they had.

## What is not acceptable

- Harassment, insults, or demeaning comments — about anyone, in issues, pull
  requests, commit messages, or code.
- Discrimination or slurs of any kind, including "as a joke".
- Sexual language or imagery, or unwanted attention of any kind.
- Publishing someone's private information.
- Sustained disruption: relitigating settled decisions, brigading a thread,
  or deliberately wasting reviewers' time.

## Scope

This applies everywhere the project happens: issues, pull requests,
discussions, commit messages, the wiki, and any space where you are acting as
a muxtop contributor.

## Enforcement

Report a problem by [opening a private security
advisory](https://github.com/lucasschimmel/muxtop/security/advisories/new) —
it is the only private channel this repository has, and it works for conduct
reports too. Reports are read by the maintainer only.

Responses are proportionate: a clarification, a warning, having a comment
removed, or being blocked from the repository. Reports are handled in
confidence, and reporting in good faith will never be held against you — even
if the conclusion is that no action was warranted.

muxtop is maintained by one person, which means enforcement is one person's
judgement. That is a limitation worth naming rather than dressing up as a
process.

*Written for this project rather than adopted from a template. If you would
